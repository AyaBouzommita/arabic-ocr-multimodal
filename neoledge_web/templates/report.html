1. Abstract & The Core Challenge

Standard Optical Character Recognition (OCR) systems are heavily optimized for Latin-based, left-to-right languages. This project tackled the uniquely difficult challenge of digitizing complex, noisy administrative documents and exams that contain a chaotic mix of right-to-left cursive Arabic and left-to-right French text.

24.3% Initial CER
18.6% Hybrid CER
2.7x Speedup
+73% YOLO mAP Gain

This report documents the creation of a multi-model hybrid pipeline. Rather than relying on a monolithic engine, we engineered a system that chains specialized layout detectors, dual OCR engines, image enhancement algorithms, and NLP spell-checkers to aggressively drive down Character Error Rates (CER) and Word Error Rates (WER).

3. Layout Parsing: The YOLOv11s Fine-Tuning Strategy

Solving the 2.7x Speed Bottleneck

Feeding an entire document into PaddleOCR/EasyOCR is highly inefficient. Background noise, table borders, and rubber stamps trigger false positives, wasting GPU cycles and destroying overall accuracy.

3.1 The YOLOv11s Architecture

We evaluated several YOLO variants. According to our generate_finetuned_report.py metrics, the 9-Million parameter YOLOv11s provided the optimal balance:

  • Base YOLOv11s: mAP50 = 0.821, mAP50-95 = 0.465
  • Fine-Tuned YOLOv11s: mAP50 = 0.962, mAP50-95 = 0.8069

Training on 300 custom document images yielded a massive +73.5% gain in mAP50-95.

3.2 Implementation: Smart Stamp Masking

One of our most critical innovations was actively masking non-text artifacts out of the image array before OCR processing. Here is the exact implementation from run_yolo_easyocr_pipeline.py:

# Mask out non-text regions (stamps, signatures, pictures, QR codes)
# to prevent OCR from hallucinating text inside them.
if cls_name in {"stamp", "signature", "picture", "qr_code"}:
    x1_int, y1_int = max(0, int(x1)), max(0, int(y1))
    x2_int, y2_int = min(w, int(x2)), min(h, int(y2))
    # Fill with white (assuming document background is mostly white)
    cv2.rectangle(image, (x1_int, y1_int), (x2_int, y2_int), (255, 255, 255), -1)
    continue
By implementing YOLO pre-cropping, we dropped total document processing time from 18,658 ms (PaddleOCR full-page scan) down to 6,872 ms — a massive 2.7x speedup while simultaneously dropping the CER from 1.30 to 1.25.

4. The Language Routing Crisis

Because we utilized PaddleOCR for French and EasyOCR for Arabic, the pipeline needed to dynamically detect the document's language and route the image crops to the correct engine.

4.1 The Sampling Failure on Bilingual Exams

Our initial logic sampled 10 random bounding boxes to check for Arabic characters. We tested this on a real bilingual exam (Arabic-I_page-0001.jpg).

Figure 2: The bilingual exam paper. Note that the top 80% is in English, while the Arabic questions are localized at the bottom.

Because the top of the exam is entirely English, the sampling algorithm found zero Arabic characters and erroneously sent the Arabic text at the bottom to the French model, resulting in disastrous outputs like WjWWb (A) B.

4.2 The Full-Page PaddleOCR Fix

We discarded the sampling logic and implemented a lightning-fast, full-page scan using PaddleOCR. If it detects even 3 Arabic characters anywhere on the page, it instantly switches the entire pipeline to the BiDi-capable Arabic ensemble.

# ── RELIABLE LANGUAGE DETECTION ──
# Scan the entire image with PaddleOCR to detect if any Arabic exists anywhere
is_rtl = False
is_arabic_detected = False
total_arabic_chars = 0

if paddle_ar is not None:
    try:
        paddle_res = paddle_ar.ocr(str(image_path), cls=False)
        if paddle_res and paddle_res[0]:
            for line in paddle_res[0]:
                text = line[1][0]
                for char in text:
                    if '\u0600' <= char <= '\u06FF':
                        total_arabic_chars += 1
    except Exception as e:
        pass

# If we find even a single Arabic word (e.g. 3+ characters), switch ensemble!
if total_arabic_chars > 3:
    is_rtl = True
    is_arabic_detected = True

5. Computer Vision: The Arabic Enhancement Pipeline

Arabic script is highly sensitive to degradation; losing a single pixel can transform a 'ب' (ba) into a 'ت' (ta). To combat this, we engineered a dedicated OpenCV enhancement pipeline (ocr/preprocessing/image_enhancer.py).

Figure 3: `temp_enhanced.png` — An intermediate crop after applying CLAHE and Bilateral Filtering.

def enhance_crop_arabic(self, image: np.ndarray, target_height: int = 128) -> np.ndarray:
    h, w = image.shape[:2]

    # 1. Upscale small crops (Arabic dots need at least ~128px height)
    if h < target_height:
        scale = target_height / h
        image = cv2.resize(image, (int(w * scale), int(h * scale)), interpolation=cv2.INTER_CUBIC)

    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)

    # 2. Bilateral filter (gentler settings for Arabic stroke preservation)
    gray = cv2.bilateralFilter(gray, d=9, sigmaColor=75, sigmaSpace=75)

    # 3. CLAHE contrast enhancement
    clahe = cv2.createCLAHE(clipLimit=3.0, tileGridSize=(8, 8))
    gray = clahe.apply(gray)

    # 4. Unsharp masking — sharpens stroke edges and character dots
    blurred = cv2.GaussianBlur(gray, (0, 0), sigmaX=2)
    gray = cv2.addWeighted(gray, 1.5, blurred, -0.5, 0)

    return cv2.cvtColor(gray, cv2.COLOR_GRAY2BGR)

6. NLP Auto-Correction: AraBERT Masked Language Modeling

Even with advanced preprocessing, visual confusion between Arabic letters is unavoidable. We developed a robust Post-Processing pipeline leveraging AraBERT (aubmindlab/bert-base-arabertv02).

6.1 Confidence & Dictionary Gating

To prevent the NLP model from destructively altering correctly extracted text, we implemented strict gating logic in arabert_corrector.py:

# GUARD 1: If confidence >= conf_threshold (e.g. 80.0), DO NOT touch!
if conf >= conf_threshold:
    corrected_words[idx] = word
    continue

# GUARD 2: If the word is already a valid Arabic word in Qalsadi/pyspellchecker, DO NOT touch!
if self.is_valid_in_lexicon(word):
    corrected_words[idx] = word
    continue

# Otherwise, attempt strict edit-distance <= 1 typo correction via AraBERT MLM
new_word, changed = self.correct_word_in_context(
    words, idx, top_k=10, max_edit_dist=max_edit_dist
)

7. Cloud Integration: Gemini Formatting & Qwen2-VL

Extracting text strings is only half the battle; reconstructing the document's structure is the final milestone.

7.1 Gemini REST API Configuration

We utilized the Gemini Flash API to receive the raw extracted text string and simply re-arrange the words and structure to make it much easier to read. The system prompt is aggressively restrictive to ensure it only formats the text without hallucinating or changing the content:

prompt = """
Extract ALL text from this document image exactly as it appears.
Preserve the original reading order and structure.
For Arabic text, maintain right-to-left reading direction.
Format the output as clean markdown.
Do NOT use any HTML tags like <div> or <span> for alignment, use pure text and markdown only.
Do NOT add any commentary, translation, or interpretation.
Preserve tables, bullet points, numbered lists.
Include dotted lines as `...........` where they appear.
"""

7.2 The Colab Tunneling Infrastructure

To support massive 7-Billion parameter Vision Language Models (Qwen2-VL-7B) for documents that exceed local processing capabilities, we built an extract_with_colab REST connector. It routes images directly to a Python 3.13 Google Colab/Kaggle GPU server via an Ngrok reverse proxy tunnel:

def extract_with_colab(image_path: str, url: str) -> str:
    url = url.rstrip('/')
    if not url.endswith('/extract'):
        url += '/extract'
    
    with open(image_path, 'rb') as f:
        headers = {
            'ngrok-skip-browser-warning': 'true',
            'Bypass-Tunnel-Reminder': 'true'
        }
        response = requests.post(url, headers=headers, files={'file': f})
        if response.status_code != 200:
            raise Exception(f"Colab API returned {response.status_code}")
            
        return response.json().get('text', '')

8. Final Quantitative Results

Our WALKTHROUGH.md and benchmark CSVs dictate the final impact of this hybrid pipeline architecture:

  • Standard EasyOCR Baseline CER: 24.30%
  • Final Hybrid Pipeline (YOLOv11s + Easy/Paddle Ensemble + AraBERT/RoBERTa) CER: 18.63%
  • Total Error Reduction: 5.67 percentage points absolute (a ~23% relative reduction in character errors across complex mixed documents).

By shifting from a monolithic OCR approach to an autonomous, multi-agent hybrid architecture, Neoledge-OCR successfully digitized degraded, heavily stamped bilingual documents with a speed and accuracy fundamentally impossible for standard open-source OCR engines.
